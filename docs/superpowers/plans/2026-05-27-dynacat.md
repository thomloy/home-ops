# Dynacat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Glance with Dynacat (`panonim/dynacat:2.3.0`) for built-in SSE auto-refresh, rename the deployment fully (directory, labels, secret/configmap names) from `glance` to `dynacat`, change the hostname from `glance.${SECRET_DOMAIN}` to `home.${SECRET_DOMAIN}`, and update the Tandoor CiliumNetworkPolicy cross-namespace allowlist accordingly.

**Architecture:** Same bjw-s `app-template` 4.6.2 HelmRelease shape as Glance — single controller, single container, two ConfigMaps (config + bg), Service, HTTPRoute, CNP, ExternalSecret. Only deltas: image, config file path (`/app/config/dynacat.yml` per Dockerfile ENTRYPOINT), one new per-widget field `update-interval: 30s` on the Infra Custom API widget. The rename is mechanical (global `glance` → `dynacat` plus a few hostname/image-specific replacements) and validated by a grep gate before commit.

**Tech Stack:** Flux CD, Kustomize, bjw-s app-template 4.6.2, `panonim/dynacat:2.3.0`, External Secrets Operator + 1Password Connect, Cilium L3/L4 NetworkPolicy, Envoy Gateway, ExternalDNS.

**Spec:** `docs/superpowers/specs/2026-05-27-dynacat-design.md`

## Rollback

If dynacat misbehaves badly post-merge:

```bash
git revert <merge-sha>
git push
flux reconcile source git flux-system
flux reconcile kustomization cluster-apps -n flux-system
```

Flux will recreate the glance directory identically (same configmaps, same secret name, same image v0.8.4, same hostname `glance.${SECRET_DOMAIN}`). The Tandoor CNP additive entry (`dynacat`) becomes a harmless no-op, and the glance entry is restored. Total time to safety: ~2 min. State loss: zero (no PVs, configmap-driven).
