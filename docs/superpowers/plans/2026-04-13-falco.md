# Falco Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Falco runtime security monitoring to the `observability` namespace, routing all events to Victoria Logs and critical events (≥ warning) to Alertmanager.

**Architecture:** Falco DaemonSet runs on every node using the `modern_ebpf` driver to capture syscalls. Falco Sidekick (subchart, deployed as a Deployment) receives events from Falco and forwards them to two outputs: Victoria Logs via its Loki-compatible API (all events) and Alertmanager (warning+ only). Both components expose ServiceMonitors for Prometheus scraping.

**Tech Stack:** Falco 8.0.2 Helm chart (`oci://ghcr.io/falcosecurity/charts/falco`), Flux OCIRepository + HelmRelease, Kustomize.

---
```yaml
# yaml-language-server: $schema=https://kubernetes-schemas.pages.dev/source.toolkit.fluxcd.io/ocirepository_v1.json
apiVersion: source.toolkit.fluxcd.io/v1
kind: OCIRepository
metadata:
  name: falco

  interval: 15m
  layerSelector:
    mediaType: application/vnd.cncf.helm.chart.content.v1.tar+gzip
    operation: copy
  ref:
    tag: 8.0.2
```

## Task 2: Create HelmRelease

**Files:**
- Create: `kubernetes/apps/observability/falco/app/helmrelease.yaml`

- [ ] **Step 1: Create the HelmRelease manifest**

```yaml
---
# yaml-language-server: $schema=https://kubernetes-schemas.pages.dev/helm.toolkit.fluxcd.io/helmrelease_v2.json
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: falco
spec:
  chartRef:
    kind: OCIRepository
    name: falco
  interval: 1h
  values:
    driver:
      kind: modern_ebpf
    falco:
      json_output: true
      json_include_output_property: true
      metrics:
        enabled: true
        prometheus_metrics_enabled: true
    serviceMonitor:
      create: true
      interval: 15s
    falcosidekick:
      enabled: true
      config:
        loki:
          hostport: "http://victoria-logs-server.observability.svc.cluster.local:9428"
          minimumpriority: "debug"
          format: "json"
        alertmanager:
          hostport: "http://kube-prometheus-stack-alertmanager.observability.svc.cluster.local:9093"
          minimumpriority: "warning"
      serviceMonitor:
        enabled: true
```

- [ ] **Step 2: Commit**

```bash
git add kubernetes/apps/observability/falco/app/helmrelease.yaml
git commit -m "feat(falco): add HelmRelease with Sidekick"
```

```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization

  name: falco

    - name: kube-prometheus-stack
    - name: victoria-logs
```

- [ ] **Step 2: Open a PR or check GitHub Actions**

The `flux-local.yaml` workflow runs on PRs targeting `main`. If pushing directly to main, Flux will reconcile within the next `interval: 1h` cycle (or trigger manually with `flux reconcile kustomization cluster-apps --with-source`).

To verify Flux picks up the changes once merged:

